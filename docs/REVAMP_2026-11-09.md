# Revision 2026-11-09: realism, walkthroughs on the hardware, bilingual UI

中文摘要：三维模型换了材质和细节（阻焊油墨、塑封料、铁氧体、研磨过的硅背面、SRAM 与逻辑区的纹理），裸片按 NVIDIA 全芯片框图重新排布，第六个 HBM 位置、底部填充胶和拆开才看得到的中介层凸点与走线补上了；地址翻译、像素和堆叠三个流程不再用独立的概念场景，而是在同一块 H100 / A100 上逐层播放；界面和全部内容有中英两种语言；按 unslop 的规则重写了文案和界面细节；新增 i18n 完整性测试和真实浏览器的整页点击测试。

## 1. 3D realism

### What a real H100 SXM shows, and what it doesn't

| Detail | Physically visible? | Decision |
| --- | --- | --- |
| Solder mask, silkscreen reference designators, fiducials, via fields, faint copper pours | Yes, on the board top | Added to the board texture. The old “GPU EXPLORER / SXM MODULE” slogans were removed; real boards carry reference designators, not slogans. |
| Molded inductors, power stages, MLCCs, tin terminations | Yes | Re-materialed: matte ferrite, black epoxy, tan ceramic, metallic tin; `R22` value marks kept. |
| Nickel stiffener ring, substrate capacitors | Yes | Kept, metal finish corrected. |
| GPU die from above | Only the ground silicon back; no circuitry | Dark mirror-like silicon with faint grinding arcs. The large “GH100” print and the rainbow iridescence were removed. |
| HBM stacks | Silicon top, black mold compound on the sides; tops level with the die | Re-modelled: matte molded layers, silicon top, faint laser mark, height brought level with the die (the old stacks stood well above it). |
| Sixth HBM site | Package photos show six stack positions; NVIDIA states five are active | Drawn as a stack-sized part marked “not enabled”. Previously H100 showed an empty pad and A100 showed nothing. |
| Underfill at the die/stack edges | Yes | Added as a dark epoxy fillet that closes the gaps. |
| HBM-to-GPU wiring in the interposer | No. It runs in the interposer's metal layers under the dies and underfill; the real layout is not public | Not drawn on the assembled package. Taking the package apart reveals microbump fields and an illustrative wiring bundle per stack, labelled as illustrative. The stacking walkthrough makes the dies translucent on that step so the wiring is visible. |
| Die floorplan | Not visible on a packaged part; die shots show blocks, not wires | The die view follows NVIDIA's full-GPU block diagrams (GH100 Fig. 3 / GA100 Fig. 4): two rows of four GPCs around a two-part L2, memory controllers along the HBM edges, PCIe/GigaThread and NVLink at the ends. SMs are disabled in TPC pairs to match the products (H100 66/72 TPCs, A100 54/64 in 7 GPCs). SRAM blocks get a regular array texture and logic blocks an irregular cell texture, the visual cue a die shot actually gives. |
| Data paths between SM blocks | No, they are logical; NVIDIA's SM diagrams don't draw them | Shown only (a) inside walkthroughs when a step uses them and (b) through an opt-in **Paths** button in Anatomy, with the note “paths show function, not where the metal runs”. Off by default to keep the anatomy uncluttered. |
| Cold plate / heatsink | Yes on a server | Left out: it would hide everything. The heat step says so. |
| NVIDIA logos, real part numbers | Yes | Left out on purpose (no vendor artwork). |

The SM view stays a functional diagram (legend colours are needed to identify resources), but the blocks now read as silicon areas rather than painted plastic: lower gloss, SRAM vs logic texture, darker partition frames. Lettering was the main complaint: the uppercase monospace engraving (“SMSP 0 · WARP SCHEDULER”, “192 KB · L1 DATA / SHARED”) was replaced by smaller sentence-case labels in the interface font, in Chinese or English, drawn with lower contrast. All surface labels redraw in place when the language changes.

## 2. Walkthroughs on the hardware

The separate concept scenes (`concept-models.js`) are gone. Each step now names a hardware level, an explosion amount and a camera (`state.js` → `guideFor`), and `teaching-flow.js` draws its routes and markers on that level of the same model:

| Walkthrough | Levels it moves through |
| --- | --- |
| Matrix multiply | board → HBM → die → package → SM ×3 → package (unchanged path, re-routed for the new die layout) |
| Address translation | SM (LD/ST forms the VA) → SM (L1 TLB miss) → die (shared TLB → GMMU) → package (page-table reads in HBM, see-through die) ×2 → die (PA, TLB fill) → HBM (controller → channel → bank) → SM (registers) |
| One pixel | die (graphics TPC) → package (vertices from HBM) → SM (vertex shader on FP32) → die (raster at the GPC) → SM (fragment shader) → SM (TEX + L1) → package (ROP side of L2 → framebuffer in HBM) → board (out through the SXM connector) |
| Why stacked | board (bandwidth) → HBM (layers) → HBM taken apart (TSVs, microbumps) → HBM (1024-bit channels) → package taken apart, dies translucent (interposer wiring) → package fully apart, side view (silicon to PCB) → package (heat) → die (disabled TPCs, unused sixth HBM controller) |

Content changes for accuracy:
- Address translation was an x86-64 CPU page walk. It is now a GPU walk using the Hopper GMMU layout from NVIDIA's open-source driver (`kern_gmmu_fmt_gh10x.c`: 57-bit VA; PD4[56], PD3[55:47], PD2[46:38], PD1[37:29], PD0[28:21], 2 MiB page offset [20:0]). The example address `0x7f3ac2d64a40` gives PD4 0, PD3 0, PD2 508, PD1 470, PD0 22, offset `0x164a40`; with page base `0x24e000000` the physical address is `0x24e164a40`. TLB sizes/locations and the GMMU's position are not published and are labelled as such.
- The pixel journey states that only two TPCs on H100 run graphics shaders and that H100 has no display output (NVIDIA Hopper article); raster and ROP placement is marked “by function”.
- The stacking journey uses product numbers from NVIDIA's spec pages: 3.35 TB/s and up to 700 W (H100 SXM), 2,039 GB/s and 400 W (A100 80GB SXM); the per-line rate (≈5.2 / ≈3.2 Gb/s) is computed and tested.

## 3. Copy and UI (unslop)

Applied the unslop audit (heydamir/unslop, CC BY 4.0) to both languages:
- Removed uppercase tracked labels (“GUIDED WALKTHROUGH”, “A HANDS-ON FIELD GUIDE”, “SOURCES & ARCHITECTURE”, 3D lettering), 7–9 px text (now ≥ 11 px), the gradient on the active nav row, the glowing dot, Georgia italics, and mixed unicode glyph icons (⟳ ↔ Aa ⌖ ◇ ↺ × ⇄ ▧ ▱) in favour of one inline line-icon set at 16 px / 1.5 stroke.
- One graphite ramp, one sage accent (the board's solder-mask green), the primary button as off-white on dark, 4 px spacing, 8/12/14 px radii, one easing curve.
- Rewrote headings to say what happens (“先搬近，再反复用” stays; “一块模组，各司其职。” became “SXM 模组”), dropped trailing periods on headings, removed defensive and stilted phrasing, wrote English as English rather than a translation.
- Fixed copy that was wrong for most journeys: the last-step button said “本次计算完成” (calculation done) for every journey.

## 4. Bilingual

`i18n.js` holds the UI dictionary and the language logic; data modules store text as `{zh, en}`. Language comes from `#lang=` in the link, then local storage (`gpu-explorer-lang`, wrapped in try/catch), then the browser language. The switch is in the top bar; changing it redraws 3D lettering, labels and overlays in place without rebuilding the model or moving the camera.

## 5. Tests

- `./run_tests.sh` (Node, no browser): state and navigation; every step's level/explode/camera and text limits; GEMM, GMMU field and physical-address arithmetic, barycentric colour, HBM per-line rate, and agreement between the lab numbers and the step text; i18n completeness (dictionary pairs and placeholders, every data string bilingual, no hard-coded Chinese outside bilingual pairs in any source file or in `index.html`, every key used exists, detection order, storage that throws); die floorplan counts; SM resource counts and picking; surface-label language switching; overlays for every step of every walkthrough on both models; served assets and a single asset version.
- `./run_e2e.sh` (real Chromium): see the README for the list and the configuration variables.

Removed with their modules: `concept-models.js`, `scene-map.js` (legacy schematic, unused by the renderer) and `lesson-story.js` (folded into `state.js`), and their tests.

## Bugs found and fixed

In the version before this revision:
1. The address, pixel and stacking walkthroughs ran in separate abstract scenes, unrelated to the hardware shown in Anatomy.
2. ArrowRight on the last step (and ArrowLeft on the first) silently replayed that step: the index was clamped and the guide re-entered.
3. The last-step button read “本次计算完成” (calculation complete) on every walkthrough, including address translation, pixel and stacking.
4. The worked-example panel was cached by walkthrough and step only, so switching the model did not refresh it.
5. Content: a GPU product page taught an x86-64 CPU page walk; the pixel walkthrough ended at a display scan-out that H100 does not have.
6. Geometry: HBM stacks stood far above the die (one cold plate could not touch both); H100's sixth HBM site was an empty pad and A100 had none; A100's GPCs had 18 SM slots (GA100 has 16); SMs were disabled singly (17-SM GPCs) instead of per TPC.

Found by the new browser tests while building this revision, and fixed before release:
7. `[data-journey]` selectors also matched `<body data-journey>`, so the first language switch threw and left the breadcrumb in the old language.
8. The overlay dataset kept the previous walkthrough after returning to Anatomy.
9. The step footer (Next) stayed visible in Anatomy on desktop.
10. English punctuation fell back to the CJK font on systems without a Latin UI font (“hasn’ t”).
11. A translucent material on stacked dies accumulated to an opaque white block; replaced by glass shells.
